# Agent provenance

The bundled graph, Claude provider, prompts, material reader, section reader, and report writer now match commit [`80b9bbd7939fc4fbc7fad9f1c8e8c55429c43450`](https://github.com/SAAF-Project/Executive-Summary-Writer/commit/80b9bbd7939fc4fbc7fad9f1c8e8c55429c43450). The HTTP contract remains version 1. Finding owners and the report header are mapped into the frontend's editable fields. Summary-length limits run in the shared provider. The upstream PowerPoint writer and command-line trace/replay are separate from the browser export path. The browser exports the reviewed original deck through `src/lib/report.ts`. Its shared `report-fit.ts` measures glyph widths against the original cells, includes headings and the grade definition, fits fonts down to 8 pt, and redistributes finding rows within the original table rectangle. Preview and export share explicit line breaks and font sizes. Oversized text blocks approval and export without truncation. This browser path does not invoke the upstream writer.

The shared modules under `upstream/` are the repository's `scripts/` versions. The bundled `run.py` retains the earlier command-line entry point and is not used by the HTTP app. Run recording and offline replay require the repository's full command-line runner and are not exposed in the frontend.

ESWriter imports this commit's real `build_graph`, Claude provider, prompts, labelled findings-material helpers, and summary / recommendation formatting from `report_writer`. The runnable app uses Claude; the upstream offline provider is not included or exposed in it. Additional `presentation.py` code reads the deck before the interview and maps the graph's actual structured output to the original summary cells. It does not create a second summary-generation or grading workflow. The graph owns the grade recommendation and confirmation. The presentation provider reuses the exact upstream grading prompt while extending its response with validated slide references and an optional unset grade. If evidence is insufficient, the wrapper asks for a clarification and resumes the same grading node with that evidence; it never substitutes a default letter. The upstream A–D confirmation parser remains unchanged.

The browser applies human-reviewed edits into the original Open XML slide parts. This retains untouched source parts rather than reconstructing the full deck. The mapped report header and finding owners can be reviewed and edited alongside the summary. The overview and other sections stay as uploaded; the upstream overview-recalculation feature is not run by browser export. ESWriter's final dropdown can override the confirmed A–D grade, with the exact reviewed definition appended to the conclusion.

Set `AGENT_REPOSITORY_PATH` to a compatible working checkout to use the team's evolving `scripts/` instead. Restart after updates. No credentials, supplied deck or repository sample binary is bundled.

The frontend service also includes the first-question change from commit [`8eb37bc`](https://github.com/SAAF-Project/Executive-Summary-Writer/commit/8eb37bc): deck analysis provides an overview, then the original graph asks its own first interview question. A deck-specific question is no longer injected. The graph modules above are unchanged. Local servers do not pull GitHub changes automatically; pull the latest `main` and restart the demo to load changes. Restarting clears active conversations and any API key entered through the temporary local setup; saved browser audits remain available.
